## 2. 发现过程

### 原记录：范围与发现链

依据 DVWA 菜单顺序进入 JavaScript Attacks。只读取 `index.php`、各安全等级的 PHP/JS 源码；没有打开真实浏览器、提交表单、触发接口或运行页面脚本。

`index.php` 明示用户输入的短语应为 `success`，随后由服务端比较 phrase 与 token：Low 用 `md5(str_rot13("success"))`，Medium 用 `strrev("XXsuccessXX")`，High 用嵌套 SHA-256 公式。Low/Medium/High 的计算算法或所需常量位于客户端脚本或服务端源码中，不能充当秘密；服务端成功分支仅拼出 `Well done!` 提示，没有发现数据库写入或账户权限变化。Impossible 分支源码明确说明客户端代码不可被保护为不可篡改。

## 5. 漏洞根因

### 报告交叉摘要

客户端脚本中的 token/验证逻辑可被查看或修改；若服务端把客户端生成结果当作授权依据，客户端控制就不是安全边界。源码显示成功提示本身不意味着后端写入或权限改变。

## 6. Patch diff 与修复建议

### 报告交叉摘要

敏感权限与业务规则在服务端重新验证；客户端 token 仅作界面流程辅助，不能充当授权；CSRF token 与业务授权分开设计。

## 8. 限制与未验证项

### 原记录：结论与边界

- **代码明示**：客户端可见的计算规则与服务端比较值是确定的；“token”不是秘密或不可伪造的凭据。
- **影响范围**：按当前源码，成功结果只是页面提示；未发现由该提示触发的持久化改动或权限提升。因此本模块表现为客户端逻辑可重现的教学题，不据此报告为真实认证绕过。
- **未验证**：没有向模块发送任何表单请求，没有计算或提交 token，也没有浏览器运行时证据；本阶段是静态源码结论。
- **修复建议（未应用）**：不要把客户端生成的哈希当成授权证明。真实业务中应在服务端执行权限/业务规则校验；CSRF 由 session 绑定的随机 token 单独处理。若目标只是教学短语挑战，可由服务端直接校验短语，不应宣称客户端算法提供安全性。
- 主 DVWA 源码和数据库未修改。源码副本与静态分析记录见本目录 `evidence/`。
